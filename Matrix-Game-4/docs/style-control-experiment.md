# 风格可控性实验：prompt 与代理配色能否改变渲染风格

> 问题：能否在**不改权重**的前提下，让 Matrix-Game 4.0 渲染出另一种美术风格
> （例如把我们自己的游戏做成水墨、赛璐璐、赛博朋克）？
>
> 结论先说：**不能。** 风格完全锁死在每个场景各自的 checkpoint 里。

---

## 1. 实验设计

固定不变：输入低模视频、场景 `ancient-egypt`、`--preset rocm`、480×864、48 帧、同一随机种子。

只改两件事，分别测：

| 组 | 变量 | 具体做法 |
| --- | --- | --- |
| A | **文本 prompt** | 三个版本：默认（写实 AAA）、水彩手绘、赛博朋克夜景、"中世纪城堡+雪景+赛璐璐动画" |
| B | **代理配色** | 把输入低模视频做 `hue=h=140:s=1.6`（色相大偏移 + 提高饱和度），几何完全不变 |

prompt 设计原则：保留"a third-person shooter game in an ancient Egyptian desert city"
这一场景前缀，只替换后半段的风格描述，避免因为场景主语改变而导致 OOD。

## 2. 结果

### 2.1 文本 prompt

| 配置 | prompt 长度 | 渲染耗时 | 画面 |
| --- | --- | --- | --- |
| 默认 | 319 字符 | 5.04 s | 写实沙漠，白天 |
| 水彩 | 266 字符 | 5.10 s | **与默认几乎相同** |
| 赛博朋克夜景 | 260 字符 | 5.18 s | **与默认几乎相同**，没有霓虹、没有夜色 |
| 中世纪城堡+雪景+赛璐璐 | ~170 字符 | ~5 s | **仍然是写实沙漠**，没有雪、没有城堡、没有描边 |

量化（第 20 帧全局统计）：

| 对比 | 平均 RGB | 饱和度 | 平均像素差 |
| --- | --- | --- | --- |
| 默认 | (103, 83, 62) | 47.2 | — |
| 水彩 | (102, 83, 63) | 46.1 | 20.8 / 255 |
| 赛博朋克 | (99, 81, 61) | 45.1 | 21.3 / 255 |

平均 RGB 与饱和度差在 1–4/255 之间——**在噪声范围内**。那 20/255 的平均像素差来自
自回归轨迹的细节分叉（同一配置跑两次也会有同量级的差异），不是风格差异。

### 2.2 代理配色

| 配置 | 平均 RGB | 饱和度 | 平均像素差 |
| --- | --- | --- | --- |
| 原始代理渲染 | (104.8, 85.2, 63.2) | 48.5 | — |
| 色相偏移代理渲染 | (104.5, 86.2, 64.1) | 48.2 | 23.4 / 255 |

输入代理已经是粉/青/绿的强烈配色（见 `captures/style-hue.png` 第二行），
渲染结果（第四行）**依旧是原来的沙岩色**。

## 3. 为什么无效

训练时**每个场景只有一个固定 caption**：SFT 与蒸馏阶段的所有样本都用同一句话，
且低模代理的颜色是先验固定的（引擎里那套材质）。于是模型学到：

- 几何 ← 代理（强约束，必须跟随）
- 外观 ← 权重先验（caption 与代理颜色都是常量，没有任何梯度要求它去关注）

文本编码器输出确实被喂进了 cross-attention（`prompt_embeds` 每块都传），
但训练中没有"同一场景不同 caption → 不同外观"的样本，
所以这条条件分支实际上退化成了常量。

这与官方设计一致：**一个场景一个模型**（castle / ancient-egypt / racing 各自微调），
风格是场景的一部分，不是可调参数。

## 4. 那怎样才能拿到自己的风格

按成本从低到高：

| 路线 | 做法 | 成本 | 可控性 |
| --- | --- | --- | --- |
| **后处理风格迁移** | 在渲染输出上再跑一个轻量风格化网络（AnimeGAN / 快速 neural style） | 低（推理侧，~5–15 ms/帧） | 中：能改画风，但会出现与几何轻微不符的笔触 |
| **LoRA 微调** | 用自己的引擎采集配对数据（低模 + 高清目标风格），对 5B 基座做 LoRA | 高：官方用 64 卡、114k 片段、4000 步 | **高**：这是唯一能真正改风格的路线 |
| **换基座** | 用通用视频模型（如 CWM 那类 proxy-conditioned 模型），prompt 可控 | 中：需要重搭推理栈 | 高，但失去"为单卡实时优化"的工程红利 |
| ~~prompt 工程~~ | ~~改 caption~~ | 0 | ❌ 实测无效 |
| ~~改代理配色~~ | ~~给低模换调色板~~ | 0 | ❌ 实测无效 |

**建议**：如果只是想要"我们自己游戏的画风"，后处理风格迁移的性价比最高；
如果目标是"模型原生就画出我们的风格"，必须走 LoRA 微调，且要有配对数据采集管线。

## 5. 复现方式

```powershell
# A 组：换 prompt
matrix-game render --scene ancient-egypt --input <低模视频> --resources resources `
  --size 480x864 --prompt "<任意风格描述>" --output <目录>

# B 组：换代理配色
ffmpeg -i <低模视频> -vf "hue=h=140:s=1.6" -c:v libx264 -crf 14 proxy-hue.mp4
matrix-game render --scene ancient-egypt --input proxy-hue.mp4 --resources resources `
  --size 480x864 --output <目录>
```

`captures/style-hue.png`（配色组）。
